# 运行契约与设计边界

仅在需要排查生命周期、通知或恢复问题时阅读本参考。

## 分层执行

同步/原生等待是第一选择。监督器用于有限、非交互且需要持久化管理的 Linux 作业，
不是替代 Codex 的调度器，也不是依赖外部消息自动恢复模型的服务。

- 监督进程脱离启动客户端，等待执行守卫退出。
- 守卫订阅命令、监督进程和信号的事件，管理作业安全期限。
- Linux pidfd + selectors 等待退出；不忙等、不按固定间隔读取状态文件。
- 一个管理进程异常退出时，另一方负责已知任务的清理和结果保存。
- 独立进程组执行 TERM → 有界退出等待 → 必要时 KILL；根命令有 PDEATHSIG 保护。
- PID 身份包含 Linux boot ID 和 /proc 启动 ticks，不按裸 PID 操作恢复任务。
- 每任务两个 Python 管理进程，任务结束后退出，没有常驻服务或第三方运行依赖。

## 状态与数据

状态：`pending / running / completed / failed / timed_out / cancelled`。

每个任务保存命令 argv、cwd、thread_id、恢复 context、各进程 PID/身份、启动与结束时间、
安全期限、退出码、错误、取消/超时标记、输出路径、通知与消费者确认信息。

默认使用 UUID ID。指定 `--key` 时以 thread_id + key 派生确定性 ID，
相同 ID 的规格签名不同就拒绝启动，不能用“通知失败”作为重跑部署的理由。

`flock` 串行状态变更，JSON 临时文件 fsync 后原子替换。
根目录初始化锁定目录 inode，启动事务锁直到握手结束；恢复/等待不会抢先判定 pending 失败。
默认目录 0700、状态/日志 0600，仍应避免将凭证写进命令或输出。

stdout/stderr 写分离文件；每次 JSON 结果只附各流最近最多 16 KiB 的输出。
ack 和通知都不删除任务结果，不自动清理历史记录。需要清理时由用户明确授权、核对目标。

## 完成与取消

有限命令结束会清理其进程组残留。取消仅作用于工具创建并记录的任务。
`wait --timeout` 是等待预算而非任务超时；它返回 75，任务保持运行。
任务安全期限耗尽记为 timed_out，退出映射为 124；取消映射为 130。

命令非零为 failed；管理进程丢失且结果未知时记 failed、exit_code=null，不能猜测成功。
操作系统重启后，通过 boot ID 不一致识别失效身份，不重跑原命令。

`cleanup_complete` 必须和 status/exit_code 一并检查。
命令“执行完成”与任意后续外部副作用“恰好处理一次”不是同一保证。

## 通知

默认 disabled。可选 `--notify-json` 是一次 argv 回调，最长等待 10 秒。
它不会连接一个预设的 Codex API，也不会自行启动另一模型。

- 先保存作业终态，再尝试通知。
- 回调有身份、尝试次数、日志、退出码和发送状态；重复请求不再次发送。
- 回调非零/超时或发送者中断不覆盖原任务结果。
- delivered 只表示回调成功退出，consumed=null；独立会话消费必须另有证据。
- 通知异常的回退是原生等待和持久记录，不自动重试命令。

Codex CLI 0.162.1 中曾实测 queue 投递成功而目标活跃回合未消费。
因此默认继续依靠当前宿主的工具等待，不提前 final 后期待队列唤醒。
该测试没有证明所有版本的行为，也没有验证空闲/无人订阅会话自动恢复。

## 已知边界

- 后台监督仅 Linux/WSL2 + Python 3.11+ + pidfd；原生 macOS/Windows 走其宿主等待。
- 不保证同时强杀两个管理进程、硬断电、不可中断内核 I/O 的即时收尾。
- 不管理主动 setsid 逃离的守护进程或通过 SSH 创建的远程进程树。
- 状态目录不是对同 UID 恶意进程的安全隔离层；对不可信命令仍需适当沙箱。
- 原生 session_id 与监督器 task_id 不可混用；原生会话失效后只能依赖持久化任务数据。
- 自动选择取决于模型、技能发现与现有指令，静态配置不能保证每次触发。
